# Scam Stories Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Open TMI's results with plain-English scam stories built by fixed rules from the scan's findings, with the
harm grid, meters and findings behind a "Show the evidence" toggle.

**Architecture:** Both scanners (Python and JavaScript) add `report.pieces`, an uncapped tally of findings per
(kind, subject). A pure module (`web/lib/stories.js`) matches a recipe library (`web/lib/stories-data.js`) against
those pieces and returns a view model; `web/lib/report-view.js` renders it; both front ends (`web/app.js`,
`public/scanner/app.js`) put it first.

**Tech Stack:** Plain ES modules in the browser, no build step, no npm packages; `node --test` (Node 22); Python 3 +
pytest for the scanner.

**Spec:** `docs/superpowers/specs/2026-11-23-scam-stories-design.md` (read it first; this plan implements it).

## Global Constraints

- CSP is `script-src 'self'`, `style-src 'self'`: no inline `style` attributes or `<style>`; set custom properties
  through the CSSOM (`el.style.setProperty`), as `report-view.js` does. No new third-party code.
- English only. Every fix and story must hold in any country: no phone numbers, deadlines or amounts that only apply
  in one country (spec, "Country").
- Only masked values ever appear (`finding.masked` / `piece.example`).
- A piece is filled only by confidence `confirmed`, `high` or `medium`. `low` never fills a piece.
- Subjects: `who: "you"` accepts `account_holder` (state `yours`) and `unknown` (state `looks-yours`), never
  `third_party`; `who: "others"` accepts `third_party` only; `who: "any"` accepts every subject (used only for
  `children`).
- "Your name" is `self_name` only and always `optional: true`.
- Impact labels, exactly: `"Hard to undo"`, `"Costly"`, `"A hassle"`; sort order is that order.
- Writing rules for recipe text: title ≤ 8 words; `howItGoes` 2–3 sentences, ≤ 50 words, second person, "could" /
  "would"; `fix` 1–2 actions; no "will", "hacker(s)", "criminal(s)", "everything", "!", or all-caps words other
  than SIM, PIN, IBAN, ID, SMS. Stories about others describe the trick and how to block it, never physical harm.
- Each recipe's `source` is an official page (international body, government, police or consumer protection), in
  English, whose URL you have opened and confirmed describes that scam. Never invent a URL.
- Python and JavaScript scanners stay in step: `tests/web/scan.test.mjs` deep-equals the JS report with
  `tests/web/fixtures/stage1.json`, generated by `.venv/bin/python scripts/web_fixtures_scan.py`.

  message ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Commit only when Vivek has

### Task 2: Matching rules and the story view model

**Files:**
- Create: `web/lib/stories.js`
- Test: `tests/web/stories.test.mjs` (tests pass their own small recipe lists, so this task does not need Task 3)

**Interfaces:**
- Consumes: `buildPieces` (Task 1) from `./sensitivity.js`; `KIND_LABELS` from `./sensitivity.js`.
- Produces (all exported from `web/lib/stories.js`):
  - `IMPACT_ORDER = ["Hard to undo", "Costly", "A hassle"]`
  - `piecesFromReport(report) -> Piece[]`: `report.pieces` if it is an array, else `buildPieces(report.findings ?? [])`.
  - `matchRecipe(recipe, pieces) -> Match`, where `Match = { recipe, index, cards: PieceState[], found, total, qualifies }`;
    `PieceState = { label, state: "yours" | "looks-yours" | "others" | "missing", example: string | null, key, optional }`.
    `found`/`total` count non-optional pieces only. `qualifies` = key piece found and `found * 2 >= total`.
  - `pickStories(matches) -> { shown: Match[], more: Match[], closest: Match | null }`.
  - `storyView(report, recipes, nouns = {}) -> StoryView`:
    `{ headline, shown: StoryCard[], more: StoryCard[], closest: StoryCard | null, also: string | null, summary }`;
    `StoryCard = { id, title, scam, about, impact, howItGoes, fix, source, pieces: PieceState[], found, total }`.
    `nouns` maps kind → `[singular, plural]` for the "Also in here" line (Task 3 supplies `KIND_NOUNS`).

Rules the tests pin (from the spec, §3):
- Filling: best row = `account_holder` before `unknown`, then confidence, then the order of the piece's `kinds`.
- Sort qualifying matches by `IMPACT_ORDER`, then `found / total` (higher first), then `index` (recipe order).
- `shown` = first 3. If no `shown` match has `about: "others"` and an `others` match qualifies, the best `others`
  match replaces `shown[2]`, which moves to the front of `more`.
- `closest` only when `shown` is empty: the match with the most found pieces (ties: impact, then index); `null` if
  no recipe has any piece found.
- `headline`: N qualifying stories (shown + more) → `If this leaked, someone could try ${N} ${N === 1 ? "thing" : "things"}.`;
  none → `Not much to build with here.`
- `summary` (for "Copy my results"): none → `Nothing in my file is enough for a common scam.`; otherwise
  `Someone could try 3 things with my file: 1 hard to undo, 2 costly.` (impact counts in `IMPACT_ORDER`, lower case,
  zero counts left out, joined with ", ").
- `also`: kinds in `pieces` (any confidence) that no `shown` card uses, counts summed across subjects, top 4 by count
  then kind, as `Also in here: 4 places and 2 organisations.` (nouns from `nouns`, else `KIND_LABELS[kind]`
  lower-cased; "a, b and c" joining). `null` when there are none.

- [ ] **Step 1: Write the failing tests** in `tests/web/stories.test.mjs`, with a small inline recipe list and piece
  rows built by a local `p(kind, subject, confidence, example)` helper. Test names and key assertions:
  - `low confidence never fills a piece`: a `health` piece at `low` → `state === "missing"`, story not qualifying.
  - `unknown subject fills a you-piece as looks-yours`; `account_holder wins over unknown for the same kind`.
  - `third-party rows never fill a you-piece and you-rows never fill an others-piece` (Review Focus 2: `phone` as
    both `account_holder` and `third_party`; the you-recipe shows the account-holder example, the others-recipe the
    third-party one).
  - `a story needs its key piece and half its counted pieces`: key + 1 of 3 → qualifies; 2 of 3 without key → not;
    key alone of 3 → not; key alone of 1 → qualifies.
  - `optional pieces show but do not count`: optional `self_name` found → `found`/`total` unchanged.
  - `stories sort by impact, then completeness, then recipe order`.
  - `top three, with one place kept for a story about others`: four qualifying you-stories + one others-story →
    `shown.map(s => s.id)` ends with the others id; the displaced story is `more[0]`.
  - `closest is offered only when nothing qualifies`, and is `null` when no piece is found at all.
  - `headline, summary and also lines`: exact strings above for N = 0, 1, 3.
  - `works from findings when report.pieces is missing` (Review Focus 1): the same report with `pieces` deleted
    gives the same `shown` ids.
  - `a low-confidence-only file gets the calm result` (Review Focus 3): only `health`/`low` and `place`/`low` rows →
    `headline === "Not much to build with here."`, `shown` empty.
- [ ] **Step 2: Run and see them fail.** `node --test tests/web/stories.test.mjs` → cannot find module `stories.js`.
- [ ] **Step 3: Implement** the exports above in `web/lib/stories.js` (pure: no DOM, no imports beyond

- [ ] **Step 4: Run and see them pass.** `node --test tests/web/stories.test.mjs` → all pass;
